【Task】
请您编写一个项目自动清理skill：
1. 它能够自动扫描指定的模块下会有哪些目录被输出了需要被定期清理的文件。
2. 根据步骤一的结果自动执行文件清理。
3. 扫描并判断文件输出目录是否正确，如果不正确请提出改善建议。
4. 用户采纳后进行输出目录规范化。

【Spec】
1. 什么文件应该被清理？
应该清理的是“非源资产、非长期依赖、可再生成或会过期”的文件，主要包括：
a. 临时文件：缓存、__pycache__、.pytest_cache、.ruff_cache、.tmp、临时下载、浏览器自动化快照。
b. 一次性数据文件：某次运行生成的下载文件、调试文件、截图、测试输出、中间转换文件。
c. 时效性强的文件：日报/月报输出、FineReport 下载结果、解密后的标准化 Excel、RPA 临时下载、运行日志。
d. 周期性更新文件：本次运行会覆盖或重新生成的报表、分析产物、schema 探测结果、运行 trace。

不应该默认清理的是：
a. 源码、测试、配置、锁文件。
b. resources/ 中稳定的模板、fixture、业务输入文件。
c. Git 已跟踪文件，除非明确确认它本来就不该入库。
d. 虚拟环境，除非用户明确要求清理环境。

2. 什么是规范化的输出目录？
规范化输出目录不是“随便找个目录放产物”，而是：
a. 所有运行生成物集中到一个可清理根目录，推荐 output/。
b. 按用途分子目录，而不是散落到根目录、resources/、src/、docs/。
c. 生成物目录可整体忽略、可整体清理、可按 run_id 或日期清理。
d. 输入资源和输出产物严格分离。

合理的输出结构是：
output/
  reports/
  downloads/
  decrypted_files/
  rpa_downloads/
  screenshots/
  logs/
  tmp/
  runs/<run_id>/
  test-results/
