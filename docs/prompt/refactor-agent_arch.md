## Background
excel-generator-project是一个日报自动生成Agent。该项目分为三个模块（位于yield_report下）：报表下载、数据分析、日报生成。
当前Agent效果极不理想，因为我思维受限，太多依赖代码，无法适应用户复杂的需求。

## Task1
1. Agent架构：我此前依旧想沿用DDD架构开发本项目，但发现这种架构并不适合Agent项目。请查询资料并回答我，一个标准的Agent项目架构是什么？
2. 个人理解：其实skill架构就是一种较为理想的Agent架构。当前项目的三个模块起始对应的是个三个skill：“报表下载、数据分析、日报生成”。它们分别提供接口来让大模型调用。
3. 理想效果：用户可以再输入框中输入需求，Agent根据用户需求完成相应任务。
- 具体来说：如果我们想要实现一个固定化工作流程，不应该再是写死一套自动执行程序（像我的v1“excel_generator_project”那样），而是接收一份spec文件，其中详细记录了用户需求。之后Agent从中拆解出重要参数，例如“要下载的报表”、“要分析的数据”、“要生成的日报”，最后依次调用每个模块来完成任务。
- 设计优势：这样当用户想要修改分析流程时，只需要用自然语言修改spec文件即可，而不是让程序员修改代码。
4. Agent核心：此前我将Agent核心交给了LLM，这是因为我此前不知道Codex还有CLI。能够将Agent核心更换为Codex，也就是说：Codex通过UI接收用户需求，然后调用每个模块的执行任务。
5. 以程序为核心：由于该任务性质高度重复，所以我们还是要将尽可能重复或同性质的流程保留为代码，让Codex调用，而不是直接让Codex分析。
