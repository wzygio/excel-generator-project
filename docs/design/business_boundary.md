# 业务边界

本文定义当前项目的业务范围，用于判断新需求应该进入当前系统、暂缓，还是由外部系统承担。

## 1. IN Scope

当前项目负责：

- 从 FineReport 下载 V3 良率相关报表。
- 从本地或网络路径获取 CT 异常管理表、目标拆解表、Gap 模板。
- 从 `spotfire.xlsx` 等文件提取产品型号。
- 通过自然语言解析用户的报表获取需求。
- 对 Excel 文件做 Schema 提取和智能查询。
- 通过 Claude CLI 生成 pandas 分析代码并本地执行。
- 通过 LLM 对结构化 Schema 进行直接分析。
- 维护 V1 Excel 日报生成流水线。
- 建设 V2 良率日报自动分析与报告输出流程。

## 2. OUT of Scope

当前项目不负责：

- 替代 FineReport、MES、ERP 等上游系统。
- 长期存储生产明细数据或建设数据仓库。
- 用户权限、审计、多人协同审批等平台能力。
- 训练或微调大模型。
- 为任意未知 Excel 自动保证 100% 正确分析。
- 绕过企业安全策略或破解受保护文件。

## 3. 暂缓能力

以下能力属于方向正确但尚未完整落地：

- V2 Gap/异常/趋势分析的正式领域模型。
- V2 最终 Excel 报告生成。
- 智能查询结果到日报模块的自动沉淀。
- 完整的集成测试与端到端 UI 自动化测试。
- 更细粒度的下载进度、失败重试和后台任务队列。

## 4. 判断规则

新增需求可以进入当前系统，通常需要满足至少一项：

- 能改善良率日报源表获取。
- 能提升良率分析准确性、可追溯性或自动化程度。
- 能减少人工 Excel 处理成本。
- 能增强 V2 DDD 架构的可测试性和可维护性。

新增需求应谨慎处理，如果它：

- 需要改变上游系统权限或数据接口。
- 需要新增大体量第三方依赖。
- 会让 Core 层直接依赖业务 IO。
- 会把临时 Prompt 或实验代码固化为核心流程。
