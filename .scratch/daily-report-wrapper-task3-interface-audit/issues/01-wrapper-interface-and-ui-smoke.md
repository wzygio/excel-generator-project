## Current context

- The project-local `daily_report` skill is a Python facade that resolves the installed public generator root, invokes `scripts/daily_report_cli.py run --mode write`, and maps its JSON result into an Excel artifact.
- Configuration defaults the generator root to `~/.agents/skills/daily-report-generator`; the public CLI is expected to own its own workspace/configuration when no explicit compatibility workspace is supplied.
- The current public generator enables Mod0 and Mod1 and skips Mod2–Mod4. Its default source mode is CT.
- Focused wrapper and Streamlit service tests pass, but they mock the external CLI. They do not prove that the UI can invoke the current installed generator and expose the resulting workbook for download.

## Desired outcome

The project wrapper remains decoupled from daily-report business rules and can invoke the current installed generator through its documented public CLI. The Streamlit UI must successfully start, generate the current-day Mod0–Mod1 workbook, and expose the generated Excel workbook through its download control.

## Acceptance criteria

- [ ] Configured and explicit generator-root resolution identifies the current installed `daily-report-generator` CLI without embedding its business configuration in the wrapper.
- [ ] The wrapper command uses the public CLI, forwards explicit report date/time only when supplied, and omits compatibility workspace overrides by default.
- [ ] The wrapper returns the generated workbook as an Excel artifact and exposes the executed workflow as `mod0`, `mod1` for the current generator configuration.
- [ ] The Streamlit UI starts from the supported launcher, accepts the default current-day flow, reports success, and presents a working download control for the generated workbook.
- [ ] Smoke verification does not alter source workbooks or re-enable Mod2–Mod4.
- [ ] Focused automated tests cover command construction/result mapping and the UI service download mapping; existing unrelated worktree changes remain untouched.

## Out of scope

- Reimplementing daily-report business logic, Mod0/Mod1 calculations, or FineReport automation inside this project.
- Migrating or enabling Mod2–Mod4.
- Redesigning the Streamlit UI beyond changes required to surface a correct generator result or download.
